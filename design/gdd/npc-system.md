# NPC 系统

> **Status**: In Design
> **Author**: Player + Claude
> **Last Updated**: 2026-06-09
> **Implements Pillar**: 关系即游戏（NPC 是关系网络的实体基础）

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `职级数据库`, `数据持久化`

## Overview

NPC 系统负责生成和管理游戏中所有非玩家角色。每个 NPC 不是无面孔的路人——他们有自己的职位、性格、立场、背景和仕途天花板。他们会在你的政治生涯中扮演领导、同僚、下属、商人或群众的角色。有些人会成为你的贵人，有些人会成为你的绊脚石，大多数人只是过客。

NPC 系统采用 **参数化生成** 而非手写——少量属性组合出丰富多样的人物。MVP 阶段管理 8-12 个核心 NPC（乡镇级），完整版扩展到 50+ 个 NPC 随管辖范围增长。

## Player Fantasy

你在走廊上遇到李副书记。他冲你点点头，眼神里带着上次你拒绝他提案的不满。你知道他是个「保守派」——不喜欢冒险，做事求稳。他的天花板是正科，这辈子也就这样了。但你不一样，你不想停在这里。所以他虽然现在是你上级，但你已经在盘算怎么绕开他直接跟镇长搭线。

每个 NPC 都是一个有血有肉的人，有自己的利益和局限。你对他们越好，不一定换回真心——有些人永远是白眼狼。你对某些人不理不睬，他们反而会暗中搞你。读懂人，是官场第一课。

## Detailed Design

### NPC 属性定义

每个 NPC 由以下属性定义：

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | string | 唯一标识符 | "npc_zhang_weimin" |
| name | string | 姓名 | "张卫民" |
| age | int | 年龄 | 45 |
| gender | enum | 性别 | 男/女 |
| rank | ref | 当前职级（引用职级数据库） | "正科级" |
| position | string | 当前岗位 | "镇党委副书记" |
| rank_ceiling | ref | 仕途天花板——此人最高能升到什么级别 | "正科级" |
| personality | string[] | 性格标签（1-3个） | ["保守", "务实", "记仇"] |
| faction | string | 所属派系（MVP 可为 null） | "书记系" / null |
| background | string | 简要背景故事 | "教师出身，后转行政" |
| party | enum | 党派 | "执政党" / "民主党派" / "无党派" |
| ambition | int (1-10) | 野心值——决定此人会不会主动搞事 | 7 |
| competence | int (1-10) | 能力值——决定此人办事靠谱程度 | 5 |
| loyalty | int (1-10) | 忠诚度——对此人的上级/派系的忠诚 | 8 |
| corruption_tolerance | int (1-10) | 腐败容忍度——此人有多容易被「搞定」 | 3 |

### 性格标签池

| 标签 | 含义 | 对游戏的影响 |
|------|------|------------|
| 保守 | 不喜欢变化和冒险 | 反对激进的改革提案 |
| 务实 | 看结果说话 | 政绩高的玩家更容易获得其尊重 |
| 记仇 | 被得罪后长期记恨 | 负面态度衰减极慢 |
| 圆滑 | 善于见风使舵 | 态度随玩家的权力变化而变化 |
| 正直 | 原则性强，不接受贿赂 | 腐败容忍度极低，灰色操作风险高 |
| 贪婪 | 容易被利益驱动 | 腐败容忍度高，可以用财力「搞定」 |
| 勤奋 | 工作狂 | 能力强但可能抢功 |
| 懒惰 | 得过且过 | 容易推卸责任，但不会主动找麻烦 |
| 野心 | 有上升欲望 | 可能成为竞争者，也可能成为盟友 |
| 感恩 | 知恩图报 | 帮过他一次，态度长期正向 |
| 嫉妒 | 见不得别人好 | 你晋升太快会触发负面行为 |
| 忠诚 | 对派系/上级忠心 | 不会轻易背叛，但站队后很难拉拢 |

### NPC 类型

| 类型 | 典型岗位 | 与玩家的关系 | 数量（MVP） |
|------|---------|------------|-----------|
| 上级 | 镇党委书记、镇长 | 决定你晋升的关键人物 | 2-3 |
| 同级 | 其他副镇长、其他股长 | 竞争+合作 | 2-3 |
| 下属 | 你部门的科员 | 帮你干活或给你拖后腿 | 1-2 |
| 其他干部 | 组织委员、纪检委员等 | 职能关系 | 1-2 |
| 外部人物 | 企业主、村干部、群众代表 | 利益来往 | 1-2 |

MVP 共 8-12 个 NPC，分布在一个乡镇场景中。

### NPC 生成规则

**Step 1 — 确定生成场景**：
- 初始生成：游戏开始时，根据起始职级和管辖范围生成对应 NPC
- 动态生成：晋升/调任到新环境时，生成新 NPC 替换旧环境的部分 NPC（重要关系人物可跟随）
- 事件生成：特定事件触发时生成临时 NPC（调查组成员、上访群众等）

**Step 2 — 属性随机化**：
- 每个属性在合理范围内随机生成
- 性格标签从标签池中随机抽取 1-3 个，确保不冲突（如不能同时「正直」和「贪婪」）
- 天花板基于层级分布概率（见职级数据库）随机确定

**Step 3 — 关系初始化**：
- 上级对你的初始态度：中性偏冷淡（你是新人）
- 同级对你的初始态度：中性（大家各做各的）
- 下属对你的初始态度：略正向（你是领导）

### NPC 生命周期

| 事件 | 触发条件 | 后果 |
|------|---------|------|
| 年龄增长 | 每年1月 | NPC 年龄+1 |
| 晋升 | NPC 考核达标+关系到位+有空缺 | NPC 职级提升，可能变成你的上级/同级/下属 |
| 调离 | 任期到期+平调 | NPC 从你的环境中消失，新人顶替 |
| 退休 | NPC 满60岁 | NPC 从环境中消失 |
| 被处分/免职 | 负面事件 | NPC 降级或消失 |
| 死亡 | 极低概率（疾病/事故事件） | NPC 消失，可能触发政治影响 |

> MVP 阶段，NPC 生命周期简化：不追踪 NPC 自身的晋升和调动。NPC 在当前环境中保持稳定，只在玩家晋升/调任到新环境时整体替换。

## Formulas

### NPC 生成数量

```
mvp_npc_count = 8 + random(0, 4)  // MVP: 8-12 NPCs in township
vs_npc_count = 15 + random(0, 5)   // VS: 15-20 NPCs for county level
full_npc_count = 30 + random(0, 10) // Full: 30-40 NPCs for city/province level
```

### 天花板判定

```
function determineCeiling(is_player = false):
    roll = random(1, 100)
    if roll <= 35: return 随机股级
    if roll <= 60: return 随机科级
    if roll <= 80: return 随机处级
    if roll <= 90: return 随机厅级
    if roll <= 97: return 随机部级
    return 随机国家级
```

玩家不受天花板限制。

## Edge Cases

| Scenario | Expected Behavior | Rationale |
|----------|------------------|-----------|
| NPC 性格标签冲突（如「正直」+「贪婪」） | 生成时检测冲突组合，重新抽取 | 保持 NPC 行为的一致性 |
| 环境中没有上级 NPC | 强制至少生成 1 个上级 | 游戏必须有晋升判定者 |
| NPC 数量随管辖范围增长 | 晋升时新环境 NPC 池扩大；旧 NPC 可选择带 1-2 个「自己人」到新岗位 | 关系连续性 + 环境新鲜感 |
| 同名 NPC | 姓氏从大姓池中随机，名字从双字组合池中随机——理论上可能重复但概率极低 | 不强制唯一性检测 |

## Dependencies

| System | Direction | Nature of Dependency |
|--------|-----------|---------------------|
| 职级数据库 | NPC 依赖职级 | 读取职级数据定义 NPC 的 rank 和 ceiling |
| 数据持久化 | NPC 依赖持久化 | 序列化/反序列化所有 NPC 状态 |
| 时间系统 | NPC 依赖时间 | 每年触发年龄增长 |

**下游依赖**：

| System | Nature of Dependency |
|--------|---------------------|
| 关系网络系统 | 为每个 NPC 维护态度值 |
| 事件系统 | NPC 是事件的参与者/触发者 |
| 灰色地带系统 | NPC 的 corruption_tolerance 影响腐败机会和风险 |
| 派系系统 | NPC 的 faction 属性是其基础 |
| 晋升系统 | NPC 可能占据或腾出职位空缺 |
| 主面板 UI | 显示关键 NPC 列表 |
| 关系网络 UI | 可视化 NPC 关系网络 |

## Tuning Knobs

| Parameter | Default | Safe Range | Notes |
|-----------|---------|------------|-------|
| MVP NPC 数量 | 8-12 | 6-15 | 太少缺乏官场感，太多管理不过来 |
| NPC 初始态度（上级） | 20 | 0-40 | 新人初始不被看好 |
| NPC 初始态度（同级） | 40 | 20-60 | 同级默认中性 |
| NPC 初始态度（下属） | 55 | 30-70 | 下属对领导有基本尊重 |
| 性格标签数 | 1-3 | 1-4 | 太多标签导致行为矛盾 |

## UI Requirements

| Information | Display Location | Update Frequency | Condition |
|-------------|-----------------|-----------------|-----------|
| 关键 NPC 列表 | 主面板侧边栏 | 态度变化时更新 | 始终显示（最近互动过的前5个） |
| NPC 详情面板 | 点击 NPC 弹出 | 打开时刷新 | 显示完整属性、态度、关系历史 |
| 新 NPC 出现提示 | 通知区域 | 新 NPC 生成时 | 持续到玩家点击确认 |

## Acceptance Criteria

- [ ] MVP 可生成 8-12 个 NPC，属性完整且合理
- [ ] NPC 属性无内在冲突（「正直」的 NPC 不会同时 corruption_tolerance 极高）
- [ ] 至少包含 2 个上级、2 个同级、1 个下属
- [ ] NPC 数据和状态可正确序列化到存档
- [ ] NPC 天花板按概率分布合理
- [ ] 性格标签影响 NPC 在事件中的行为倾向

## Open Questions

| Question | Status | Notes |
|----------|--------|-------|
| NPC 是否需要「家庭」属性（配偶职业、子女情况）？ | 后续 | 增加婚姻/家庭对仕途的影响维度 |
| 玩家能否主动「培养」某个 NPC（带自己人上来）？ | 后续 | 提拔下属增加人脉，但被提拔者可能反噬 |
| NPC 的头像/肖像？ | MVP 不需要 | 纯文字+颜色标识即可 |
