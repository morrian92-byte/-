# 数据持久化系统

> **Status**: In Design
> **Author**: Player + Claude
> **Last Updated**: 2026-06-09
> **Implements Pillar**: 权力是积累的（持久化是权力跨会话积累的技术保障）

> **Quick reference** — Layer: `Foundation` · Priority: `MVP` · Key deps: `None`

## Overview

数据持久化系统负责将游戏状态序列化并存储到浏览器本地，使玩家可以随时存档、读档和继续上次的游戏。它是支柱「权力是积累的」的技术保障——没有持久化，积累就只存在于内存中，会话结束就消失。

技术方案：Web 浏览器的 `localStorage`（MVP）+ 可选 `IndexedDB`（后期大数据量）。数据格式为 JSON。

## Player Fantasy

这个系统本身没有玩家可见的幻想——它是隐形的保障。但玩家在关掉浏览器、第二天打开继续的时候，看到自己半年前做的那个灰色选择仍然在档案里、经营的每一段关系还在那里——这就是持久化提供的安心感。

存档不是「作弊工具」——不能在危机时刻 S/L 大法。但它是「记忆」——记录你在官场走过的每一步。

## Detailed Design

### Core Rules

**R1 — 存储介质**（MVP）：
- 使用浏览器 `localStorage` 存储游戏存档。
- 每个存档是一个完整的 JSON 对象，包含所有系统状态。
- `localStorage` 上限通常为 5-10MB，对于文字策略游戏绰绰有余。
- 后期（Alpha+）可迁移到 `IndexedDB` 支持更大数据量和多存档。

**R2 — 存档槽位**：
- 提供 3 个手动存档槽位 + 1 个自动存档槽位。
- 每个槽位包含：存档名称（可编辑）、游戏时间戳、当前职级、简短描述。
- 自动存档覆盖最近一个自动存档槽位。

**R3 — 手动存档规则**：
- 只在 **NORMAL** 状态下允许手动存档。
- **CRISIS_PAUSED** 状态下「保存」按钮灰显，提示文本：「危机时刻，无法存档」。
- **YEAR_END** 和 **TERM_END** 结算期间也不允许存档（防止利用结算间隙 S/L）。
- 保存成功后显示简短确认（不打断流程）。

**R4 — 自动存档规则**：
- 自动存档触发时机：
  - 每年 1 月（年度自动存档）
  - 晋升发生时
  - 任期结束时
  - 重大事件发生后（被举报、巡视进驻等）
- 自动存档不覆盖手动存档槽位。

**R5 — 读档规则**：
- 读档后，游戏状态完全恢复到存档时的时间点。
- 读档后不可撤销——当前未保存的进度将丢失，需要确认。
- 读档只能在主菜单或 NORMAL 状态下进行。

**R6 — 存档数据结构**（顶层）：

```json
{
  "version": "1.0",
  "save_name": "我的存档",
  "created_at": "2026-06-09T12:00:00Z",
  "updated_at": "2026-06-10T15:30:00Z",
  "game_time": {
    "year": 2022,
    "month": 6,
    "era": "新时代"
  },
  "player": {
    "name": "...",
    "age": 28,
    "current_rank": "副股级",
    "current_position": "乡镇经济发展办副主任",
    "party": "无党派",
    "party_position": null,
    "resources": { "performance": 65, "connections": 42, "budget": 150 },
    "term_months_elapsed": 18,
    "career_history": [...]
  },
  "npcs": [...],
  "active_projects": [...],
  "active_events": [...],
  "relationships": {...},
  "gray_zone_state": {...}
}
```

**R7 — 版本兼容**：
- 存档包含 `version` 字段。
- 加载时检查版本号——如果不兼容，提示玩家（不自动迁移旧存档）。
- MVP 阶段只有一个版本，暂不做迁移逻辑。

### States and Transitions

| State | Description |
|-------|-------------|
| NO_SAVE | 无存档存在（首次游戏） |
| SAVED | 有存档，游戏状态已序列化到存储 |
| SAVE_IN_PROGRESS | 存档进行中（瞬时状态，一般不可见） |
| LOAD_IN_PROGRESS | 读档进行中 |

存档操作不改变游戏时间状态，是并行操作。

### Interactions with Other Systems

| 交互方 | 方向 | 内容 |
|--------|------|------|
| 时间系统 | 持久化→时间 | 保存/恢复当前年月、年代、任期倒计时 |
| 资源系统 | 持久化→资源 | 保存/恢复政绩、人脉、财力数值 |
| NPC 系统 | 持久化→NPC | 保存/恢复所有NPC的状态 |
| 关系网络 | 持久化→关系 | 保存/恢复态度值 |
| 事件系统 | 持久化→事件 | 保存/恢复活跃事件和事件历史 |
| 晋升系统 | 持久化→晋升 | 保存/恢复职级和晋升相关状态 |
| 灰色地带 | 持久化→灰色 | 保存/恢复腐败状态和风险 |
| UI | 双向 | 提供存档/读档界面；读取存档列表 |

## Edge Cases

| Scenario | Expected Behavior | Rationale |
|----------|------------------|-----------|
| localStorage 已满 | 提示玩家删除旧存档或导出存档。不静默失败 | 给用户控制权 |
| 存档损坏（JSON解析失败） | 标记该槽位为「损坏」，不允许加载。不自动删除 | 可能是浏览器问题或手动编辑，保留给用户检查 |
| 浏览器隐私模式下 localStorage 不可用 | 检测并提示玩家切换到正常模式或使用 IndexedDB 降级方案 | 不静默丢失进度 |
| 游戏更新后读旧版本存档 | 如果版本号不兼容，显示警告：「此存档来自旧版本，加载可能导致异常」 | 预防而非禁止 |
| 玩家关闭浏览器时未存档 | 自动存档在下次启动时可用。最多损失从上次自动存档到崩溃时的进度 | 自动存档机制兜底 |

## Dependencies

| System | Direction | Nature of Dependency |
|--------|-----------|---------------------|
| — | — | 数据持久化为 Foundation 层，零上游依赖 |

**下游依赖**：所有系统都需要向持久化系统暴露可序列化的状态数据。每个系统需实现 `getSaveState()` 和 `loadSaveState(data)` 接口。

## Tuning Knobs

| Parameter | Default | Safe Range | Notes |
|-----------|---------|------------|-------|
| 手动存档槽位数 | 3 | 1-10 | MVP 3个足够，后期可增加 |
| 自动存档槽位数 | 1 | 1-3 | 只保留最近1个自动存档 |
| 自动存档触发（年初） | on | on/off | |
| 自动存档触发（晋升） | on | on/off | |
| 自动存档触发（重大事件） | on | on/off | |
| 本地存储上限警告 | 80% 容量 | 50%-95% | 达到阈值时发出清理提示 |

## UI Requirements

| Information | Display Location | Update Frequency | Condition |
|-------------|-----------------|-----------------|-----------|
|「保存」按钮 | 主面板菜单 | — | NORMAL 状态可用；CRISIS/YEAR_END/TERM_END 灰显 |
|「加载」按钮 | 主菜单 + 主面板菜单 | — | 始终可用 |
| 存档槽位列表 | 存档/读档弹窗 | 打开弹窗时刷新 | 显示名称、时间、职级 |
| 自动存档标识 | 存档列表中 | — | 自动存档显示 ⚡ 图标 |
|「删除存档」按钮 | 存档槽位旁 | — | 需要二次确认 |
| 存储空间使用量 | 存档管理界面 | 打开时刷新 | |

## Acceptance Criteria

- [ ] 可以手动保存游戏到3个槽位之一
- [ ] 可以加载已有存档并正确恢复所有游戏状态
- [ ] 危机状态下无法存档
- [ ] 年初/晋升/重大事件时自动存档
- [ ] 读档需要二次确认（防止误操作）
- [ ] localStorage 已满时有提示，不静默失败
- [ ] 版本不兼容的存档有警告提示
- [ ] 所有 MVP 系统（14个）的状态均可序列化/反序列化

## Open Questions

| Question | Status | Notes |
|----------|--------|-------|
| 是否需要存档导出/导入功能（JSON文件）？ | 后期 | 方便玩家备份、迁移、分享存档 |
| 是否支持「铁人模式」（只允许自动存档，禁止手动存档）？ | 后期 | 硬核选项，与「不可逆」支柱高度一致 |
| Web 端是否需要云端存档同步？ | 不考虑 | 需要后端+账号系统，超出 MVP 范围 |
