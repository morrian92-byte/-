# 事件系统

> **Status**: In Design | **Layer**: `Core` | **Priority**: `MVP` | **Deps**: `时间系统`, `资源系统`, `NPC 系统`
> **Pillar**: 灰色即深度（事件是灰色地带具象化的载体）

## Overview

事件系统是《步步高升》的叙事引擎。它通过 **参数化模板 + 条件触发** 的方式生成玩家遇到的各种官场事件——从日常的「上面要来检查」到关键的「实名举报信」再到「巡视组进驻」。事件不是手写的线性剧情，而是由模板、参数和玩家状态共同生成的动态叙事。

MVP 阶段提供 12-15 个核心事件模板，覆盖乡镇官场的主要场景。

## Detailed Design

### 事件结构

每个事件由以下部分组成：

| 部分 | 说明 | 示例 |
|------|------|------|
| 标题 | 简短事件名 | "群众举报违规建筑" |
| 描述 | 2-4 句叙事，参数化填充 | "[企业主姓名]在[地点]违规建设，群众[人数]人联名举报" |
| 触发条件 | 什么情况下事件触发 | 灰色地带活跃 + 人脉 < 40 |
| 选项 2-4 个 | 玩家的应对方式 | 见下方 |
| 每个选项的后果 | 资源变化、关系变化、连锁事件 | 见下方 |
| 连锁事件 | 可能触发的后续 | "上级过问" / "不了了之" |

### 事件触发条件类型

| 条件类型 | 说明 | 示例 |
|---------|------|------|
| 时间触发 | 特定月份/季度固定可能发生 | 年度考核前 1 个月——「突击检查」 |
| 资源触发 | 资源值进入某个范围 | 政绩 < 30——「上级约谈」 |
| 关系触发 | 某 NPC 态度达阈值 | 某上级态度 < -20——「被穿小鞋」 |
| 灰色触发 | 腐败操作后的连锁 | 收受好处 → 可能触发「被举报」 |
| 随机触发 | 每月小概率随机 | 月度随机事件池 |
| 连锁触发 | 前一个事件的结果触发 | «上级过问» ← «举报» |

### 事件模板（MVP 核心池）

**日常政务类**：

| 事件 | 触发 | 选项举例 |
|------|------|---------|
| 上级调研 | 季度内随机 | A) 精心准备（财力-10，政绩+3） B) 务实汇报（政绩±0~3） C) 借机告状（关系变化） |
| 项目招标 | 有新项目时 | A) 公正招标 B) 暗示给关系户（灰色） C) 自己插手（高风险灰色） |
| 会议博弈 | 季度内随机 | A) 支持领导意见 B) 提出不同方案 C) 保持沉默 |

**关系博弈类**：

| 事件 | 触发 | 选项举例 |
|------|------|---------|
| 某人请你帮忙 | 关系 > 30 的 NPC | A) 全力帮忙（花费行动点+财力） B) 象征性帮忙 C) 婉拒（态度-10） |
| 拉帮结派 | 同级 NPC 多个 | A) 加入一方的圈子 B) 保持独立 C) 两边都敷衍 |
| 领导的暗示 | 上级态度 > 0 | A) 积极响应（表态站队） B) 装不懂 C) 明确拒绝（态度-20） |

**灰色地带类**：

| 事件 | 触发 | 选项举例 |
|------|------|---------|
| 企业主的「心意」 | 有招商项目时 | A) 拒收 B) 收下（财力+20，埋风险） C) 暗示不够多 |
| 报销漏洞 | 有项目支出时 | A) 严格审核 B) 睁一只眼 C) 自己也报点（灰色） |
| 领导让你「灵活处理」 | 上级暗示 | A) 坚决合规 B) 适当灵活（灰色） C) 超额执行（高灰色） |

**危机类**：

| 事件 | 触发 | 选项举例 |
|------|------|---------|
| 实名举报 | 灰色活跃+有人敌意 | A) 私下摆平（财力-30，消耗人脉） B) 正面回应 C) 找上级庇护 |
| 巡视组来了 | 年度/随机 | A) 一切合规应对 B) 提前销毁痕迹 C) 主动坦白（如果有问题） |
| 舆情爆发 | 项目事故后 | A) 快速回应 B) 找人删帖（灰色） C) 冷处理 |

### 选项设计原则

每个事件有 2-4 个选项。选项必须体现：
1. **取舍**：没有「万能选项」——每个选项有不同的代价
2. **灰色**：至少有 1 个选项涉及灰色操作（好效果但有风险）
3. **关系影响**：选项可能同时讨好一方得罪另一方
4. **不可逆**：选了的后果无法撤销

### 连锁事件

某些事件的结果会埋下「种子」，在未来的月份触发连锁：

```
«收下企业主的好处» → 种子：可能在 3-12 个月后触发 «被举报»
«帮了某人的大忙» → 种子：该 NPC 在关键时刻可能主动帮你
«站队错误» → 种子：派系博弈失败时被清算
```

连锁事件增加了「因果报应」的延迟感——你在 3 月份的选择可能在 8 月份才浮现后果。

## Formulas

### 事件触发概率（每月）

```
event_trigger_probability = base_rate + risk_modifier

base_rate = 0.6  // 60% 每个月至少触发 1 个事件
risk_modifier = 
    +0.1 if gray_activity_high
    +0.1 if any_npc_attitude <= -50
    -0.1 if performance > 80  // 政绩好能镇住一些事
```

### 连锁种子触发

```
seed_trigger_check():
    for each active seed:
        if seed.time_elapsed >= seed.trigger_window:
            roll = random(1, 100)
            if roll <= seed.trigger_probability:
                trigger_chained_event(seed)
```

## Edge Cases

| Scenario | Expected Behavior |
|----------|------------------|
| 多个事件同时触发 | 按优先级排队：危机 > 灰色后果 > 日常。玩家逐一处理 |
| 所有选项都涉及灰色 | 这是设计意图——某些事件就是逼你做灰色选择，测试你的底线 |
| 长期（12个月+）无事件 | 触底反弹——保证至少每季度有一个非随机事件 |
| 连锁种子在 NPC 已不存在时触发 | 种子失效，不触发 |

## Tuning Knobs

| Parameter | Default | Range | Notes |
|-----------|---------|-------|-------|
| 每月事件基础概率 | 60% | 30-90% | 太高→官场太乱；太低→太无聊 |
| 连锁触发窗口 | 3-12月 | 1-24月 | 太短→太明显；太长→断了因果感 |
| MVP 事件模板数 | 15 | 10-20 | 太少→重复感；太多→开发量大 |

## Acceptance Criteria

- [ ] 至少 15 个事件模板，覆盖政务/关系/灰色/危机四类
- [ ] 事件参数化——同一模板不同触发条件产生不同内容
- [ ] 每月事件触发概率合理（不密集轰炸也不长期空窗）
- [ ] 连锁事件正确触发（种子→延迟→事件）
- [ ] 事件中的选项体现取舍和灰色
- [ ] 事件后果正确影响资源、关系和后续事件
